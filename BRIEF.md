### Signature move: the Filling Strand-Drawing Rail

A fixed, thin schematic cross-section of the whole plant run — six nodes in
one real inline SVG line drawing: **Ansaugung → Kanal → Brandschutzklappe →
Gerät → Verteilung → Auslass** — mounted at the side edge (right on desktop,
bottom strip on mobile, consistent with where a map rail belongs in this
grammar). The line art starts fully in outline (ink-soft stroke, no fill).
As the visitor flies, the stroke's `stroke-dashoffset` and a per-segment
`fill-opacity` are driven directly off total track progress (0 to 1 across
the whole spacer, not per-leg), read every frame from the same `--sc-p`-style
mechanism the engine already publishes on `:root`. The segment matching the
current leg (via the `sc:waypoint` event) gets a brighter cyan highlight and
its label un-dims; completed segments stay filled cyan at a slightly lower
opacity; upcoming segments stay outline-only. No dots, no counter, no "3/5" —
a real technical drawing that is also the navigation, each node clickable to
jump to that leg. This is bespoke SVG + ~40 lines of plain JS reading the
engine's published progress and waypoint event; the engine itself is
untouched, matching the bar set by both prior builds' signature moves.

Why it counts as a signature move and not a parameter change (per
uniqueness.md §3 "what does not count"): it is not a recoloured spotlight, not
a kit device with a new class name, and it does something neither prior
signature move did — it is simultaneously navigation, a live progress
indicator, and a literal explanation of the product (the visitor learns the
six stages of a ventilation run by watching the drawing fill), which is the
seed the client asked for almost verbatim.

### Score: legs

All five Kling clips are 5s renders. Per worldflight.md §7c, pace is
`weight / clip_seconds` and should hold within a few percent across legs to
avoid the world surging or dragging — **unless** the peak is deliberately
given more weight, which the guardrail explicitly allows ("exceeding it is
fine and often correct; exceeding it without checking is not"). The user
asked for the peak to own "die größte Scroll-Strecke," so leg 3 is given
materially more weight than its neighbours, not just more `linger`; the
guardrail is noted and accepted deliberately, not missed.

| Leg | Waypoint | Weight (vh) | Linger | Copy window | Rate check (weight/5s) |
|---|---|---|---|---|---|
| 1 | Ansaugung (Hero) | 1.5 | 0.2 | `hero` | 0.30 |
| 2 | Kanal + Klappe | 1.5 | 0.35 | `0.18 0.33` | 0.30 |
| 3 | **Technikzentrale (Peak)** | **2.4** | **0.5** | none (rail carries it; a short label cue at the settle) | 0.48 — deliberately above the other legs, by design, see above |
| 4 | Deckenhohlraum | 1.6 | 0.3 | `0.56 0.72` | 0.32 |
| 5 | Austritt / Ankunft | 1.6 | 0.38 | `finale` | 0.32 |

Total weight 8.6 + 1 = **9.6vh** track. `data-sc-seam="0.16"`,
`data-sc-lerp="0.12"` per worldflight.md §7c's worldflight-specific defaults.

## Assets

### Budget, checked against the real balance

`kie.mjs probe` confirmed **446 credits** available right now. Published-rate
planning (assets.md): a still is 28 credits, a 5s Kling clip is 160. The
brief as given — two complete chains (16:9 and 9:16), 5 legs each plus 2 start
stills — is 2 stills + 10 clips = 2×28 + 10×160 = **1656 credits at published
rates**, well over the available balance even accounting for the ~38% actual
debit rate observed elsewhere (≈630 credits), which still exceeds 446.

**Decision, flagged to the user at the Leg 1 checkpoint rather than assumed
silently:** build the **16:9 desktop chain in full** (1 still + 5 clips ≈ 828
published / ≈315 actual-debit, comfortably inside balance), and for 9:16
mobile use assets.md's cheapest sanctioned portrait option — **compose for
both** (keep the subject centred, copy in a bottom band) and derive the
mobile `data-sc-src-mobile` files by cropping/encoding the same desktop
masters at mobile dimensions, rather than generating five more clips from
scratch. This is explicitly licensed in assets.md §"Portrait" as "cheapest,
and usually enough," and it is the only path that fits the real balance
without a top-up. Flagged plainly so the user can instead approve a credit
top-up if they want genuinely separate native-portrait footage, as the v1
build's owner did previously for a different reason.
